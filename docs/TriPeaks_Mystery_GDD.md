# 프로젝트 기획서: 탐정 솔리테어: 세계 사건 수첩 (Detective Solitaire: World Case Files · 探偵ソリティア：世界の事件手帳)

> 게임 이름: 2026-10-21 "온천 여관의 비밀"(가제)에서 변경. 홈 화면 아이콘 이름은 짧게 — 탐정 솔리테어 · Detective Solitaire · 探偵ソリティア (기기 언어별, `mobile/android/app/src/main/res/values*/strings.xml`).

## 1. 프로젝트 개요
- **장르**: 하이브리드 캐주얼 (트라이픽스 솔리테어 퍼즐 + 코지 미스터리 추리)
- **아트/분위기**: 따뜻하고 아기자기한 2D 그래픽, 잔혹하거나 공포스럽지 않은 코지 미스터리(Cozy Mystery) 톤앤매너
- **플랫폼**: 모바일 (구글 플레이 스토어 타깃)
- **볼륨 (론칭 기준)**: 총 5개 에피소드 × 20개 스테이지 = 총 100 스테이지

## 2. 에피소드 & 추리 시스템 구조

### 에피소드 1: 산속의 조용한 온천 여관
- **배경**: 눈 덮인 산골짜기에 위치한 전통 온천 여관. 평화로운 분위기 속에서 벌어진 소동 (예: 가보로 내려오는 전설의 온천 탕패 도난 사건 등).
- **진행 방식**:
  - 1개 에피소드 = 20개 스테이지.
  - 스테이지 1개 클리어 시마다 **단서(Clue) 1개** 획득.
  - 총 20개의 단서를 모두 모아야만 범인을 완벽하게 특정할 수 있는 **논리 퍼즐(Logic Grid) 구조**.

### 추리 밸런스 설계
- **용의자 구성**: 6~8명의 개성 있는 용의자 (여관 주인, 온천 관리인, 단골 손님, 요리사 등).
- **단서 난이도**: 
  - 단서 자체는 직관적이나 여러 조건이 교차 검증되어야 범인이 좁혀지는 방식.
  - *예시*: "범인은 알레르기 때문에 유자를 만지지 못했다", "사건 시각 식당에 있던 인물은 3명이다" 등.
- **최종 판결 (Stage 20)**:
  - 20스테이지 클리어 후 최종 범인 지목 인터페이스 오픈.
  - 지목 성공 시 에피소드 완결 보상 지급 및 다음 에피소드 해금.
  - 지목 실패 시 광고 시청 또는 골드 소비로 결정적 추가 힌트 제공.

### 300화 스토리 진행 (V6 데이터) · 수사 보드
- **데이터**: `data/TriPeaks_300_Episodes_V6_Sorted.csv` (제목 · 대륙 · 장소 · 진범 · 용의자들 · 동기 · 진범의 고백) → `python tools/import_episodes_v6.py` → `js/data/episodes.js` (`ep001`~`ep300`).
- **대륙 챕터 순서**: 아시아(1~100) → 북아메리카(101~140) → 남아메리카(141~180) → 아프리카(181~230) → 유럽(231~280) → 오세아니아(281~300).
- **논리 그리드 단서 (`data/V6_300_Episodes_Logic_Clues.json`)**: 에피소드마다 용의자 6명 × 장소 6곳 × 물건 6개 짝 맞추기 퍼즐. 단서 1~20은 스테이지 1~20 클리어 때 하나씩, 단서 21(결정적 힌트)은 단서 20개를 모은 뒤 보상형 광고로 해금. 범인 = 사건 현장에서 범행 도구를 가진 사람.
  - **단서 생성기 v2 (`tools/logic_gen.py`, 아인슈타인 퍼즐 방식)**: 예전 데이터는 1번 단서 문장 틀이 300화 모두 같고, 그리드 6번째 줄이 늘 진범이고, 단서 7~8개면 범인이 보였다 → 전부 새로 생성 (원본은 `data/V6_300_Episodes_Logic_Clues.v1_original.json`).
    - 정답 먼저: 용의자 6 × 장소 6 × 물건 6 무작위 배치, 진범은 그리드 1~6번째 줄 중 무작위 (300화 분포 41/54/63/47/41/54). 사건 현장에 있던 사람 = 범행 도구를 가진 사람 = 범인.
    - 정답에서 참인 단서를 23가지 유형(소거 · 확정 · 둘 중 하나 · 만약 ~라면 · 둘 다 참/거짓 · 옆방 · 앞쪽 · 물건 주인끼리 옆방 …)으로 뽑고, 같은 유형은 다른 문장으로. 단서마다 풀이기로 남은 배치 수 · 범인 후보 수를 센다.
    - 단서 1~10 = 직접 소거 위주, 11~19 = 복합 단서. **단서 19개까지 범인 후보 2명 이상 (19번째 뒤 정확히 2명)**, 단서 20에서 그리드 전체와 범인이 하나로. 단서 21(광고) = 후보 2명 중 한 명의 알리바이가 진짜이고 다른 한 명의 진술이 거짓이라는 모순 (범인을 직접 말하지 않음).
    - 장소는 그리드 왼쪽부터 복도를 따라 한 줄 (옆방 = 이웃 칸, 앞쪽 · 현관에 가까운 = 왼쪽 칸) — 그리드 머리와 사용법에 표시.
    - 난이도 3단계: 1~100 견습 탐정 · 101~200 정식 탐정 · 201~300 명탐정. 단계가 오를수록 초반 단서의 정보가 줄고(단서 10개 뒤 남은 배치 평균 117 → 280 → 1,079), 범인 후보가 오래 남고(단서 10개 뒤 평균 2.8 → 3.5 → 4.3), 복합 단서 유형이 늘어난다. 1단계도 단서 19개까지는 범인을 고를 수 없다.
    - **추측 금지 (no bifurcation)**: 퍼즐 커뮤니티 기준(해 하나 · 매 단계가 보이는 정보로 추론 가능 · 분기 금지)에 맞춰, 전파 풀이기(`propagate` — 사람별 후보 집합을 단서 규칙으로만 줄임)만으로 단서 20개에서 그리드 전체가 정해지는 세트만 채택. 300화 모두 통과 (전파만으로도 범인은 정확히 20번째에서 확정).
    - **장면화 · 변주 · 표시된 가짜 단서** (리뷰 · 설계 규범 비교 뒤 보강): 단서의 약 45%에 공간에 맞는 증인("집사의 증언:", "역무원이 기억하기로,")이나 자료 출처("감식반 보고 —")를 붙여 탐정 기분을 살린다(용의자 이름은 쓰지 않음). 에피소드마다 **거짓 증언 1건**("…에 있었다고 주장했다. 하지만 거짓으로 밝혀졌다" — 논리는 소거와 같음). 2·3단계는 **확인되지 않은 소문** 1~2개를 단서 꼬리에 붙인다(참·거짓 반반, 반드시 "확인되지 않았다"로 표시 — 가짜 단서는 표시해야 공정). 단서 21 끝에 사건의 동기 한 줄.
    - **힌트권 공급**: 상점 [힌트권] 탭 — 골드 상품 1장 250G · 3장 600G(장당 200) · 10장 1,500G(장당 150), 현금 '탐정 힌트 가방' $1.99 = 15장 + 500G. 가격 근거: 광고 1회 = 하트 1칸 ≈ 300G이고 칸 확인 1회는 광고 1회와 같은 가치 → 1장 250G(1단계 2~3판 순이익). 연승 보상 7연승 +1 · 20연승 +1 · 30연승 +2 (30연승까지 4장 ≈ 1,000G 상당, 72칸 중 4칸 — 난이도 영향 없음). 아이콘 `pack_hint_single / trio / case.png` (Higgsfield GPT Image 2.5, 기존 그림체 참조).
    - **칸 확인**(흐름 피드백): 그리드 툴바 [🎟 칸 확인] → 표시한 ✕·○ 한 칸이 맞는지 알려 준다. 힌트권 1장, 없으면 보상형 광고. 틀렸으면 정답으로 고쳐 주고, 확인한 칸은 ✓ 표시(`episode.gridVerified`). 정답은 `ep.logic.answer`.
    - 붉은 실(단서 ↔ 용의자)은 문장에 독립된 낱말로 나온 이름만 연결 (긴 이름부터 가림 — 히나 ⊂ 히나타 · 하루카+나 ≠ 카나).
    - 변환기(`tools/import_episodes_v6.py`)가 같은 풀이기로 300화를 다시 검증 (해 1개 · 범인 = 진범 · 단서 19개까지 후보 2명+). 단서 데이터가 바뀌면 저장된 그리드 메모는 비운다 (`episode.logicVer`).
    - 범행 도구 이름도 코지 톤 (수면제 든 홍차 · 밀가루 포대 · 자물쇠 · 밧줄 …, `tools/logic_themes.py`).
  - 수첩 [논리 그리드] 탭: 세로 = 용의자 6명, 가로 = [장소 6] | [물건 · 특징 6]. 칸을 누를 때마다 빈칸 → ✕ → ○, 상태는 바로 저장. 6번째 칸(사건 현장 · 범행 도구)은 붉게 강조.
  - ○를 표시하면 같은 줄(같은 그룹) · 같은 칸(다른 용의자)이 자동 ✕(흐린 표시, 저장 안 함 — ○를 지우면 함께 사라짐). 규칙: 한 사람은 장소 1곳 · 물건 1개, 한 장소 · 물건은 한 사람만.
  - 처음 그리드를 열 때(에피소드 1) 사용법 안내를 자동으로 띄우고, 이후 [?] 버튼으로 다시 볼 수 있다. 그리드 탭에서는 수첩을 화면 가득 키워 휴대폰에서도 칸을 누르기 쉽게 한다.
- **수사 보드(추리 수첩)**: 홈 [추리 수첩 보기] → 코르크 보드. 용의자 폴라로이드(최대 10명), 단서 포스트잇, 붉은 실(단서 ↔ 언급된 용의자).
  - 용의자를 자동으로 지우지 않는다 (흑백 · ✕ 도장 · 취소선 없음). 붉은 실은 단서에 이름이 나온 용의자에게만. ☆/✕ 메모는 플레이어가 직접.
  - 사진을 누르면 용의자 파일 (이름 · 나이 · 성별 · 직업 · 배경 · 관련 단서).
  - 단서 20개 → 보드 중앙 하단 [최종 범인 지목하기] → 지목 팝업 (단독 1명 / 공범 2명).
- **해결 연출**: 성공 컷씬 → 진범의 고백 (한 글자씩 타이핑, 탭하면 끝까지) → [사건 해결 완료] 도장 → 보상(1,000G · 되돌리기 1 · 와일드 1 · EXP 200, `completeCurrentEpisode`로 1회 지급 — 골드 인플레이션 방지로 하향) → 다음 에피소드.
  - 다음 에피소드의 대륙이 바뀌면 챕터 전환: "새로운 대륙 [북아메리카]로 이동합니다!" (다음 사건 배경 · 지도 · 6개 대륙 진행 점).
  - 오디오: 전환 효과음(`plane.mp3`, `TP.TRANSITION_SFX`)은 연출이 닫히는 순간 0.45초 페이드아웃, 화면이 바뀌거나 로비에 들어오면 `TP.audio.stopTransitionSounds()` · `enterLobby()`로 정리 (로비에는 홈 BGM만).
- **실패**: 기존 규칙 그대로 — 재지목 500→400→300→200→무료(광고 할인), 광고/힌트권으로 결정적 힌트(진범의 직업 · 연령대 · 동기) 3개 중 1개씩.

## 3. 솔리테어 코어 게임플레이 규칙

### 기본 룰
- **트라이픽스(TriPeaks) 방식**: 상단에 피라미드/다양한 기하학적 형태로 겹쳐진 카드 배치.
- 하단의 활성 카드(Active Card) 기준으로 **±1 (숫자가 1 크거나 1 작은) 카드**를 터치하여 제거. (K와 A는 상호 연결).
- **클리어 보장 덱 생성 알고리즘 (중요)**:
  - 덱에서 카드가 무작위로 나오는 것처럼 보이지만, 수학적으로 '반드시 클리어 가능한 카드 순서'를 역산하여 덱을 생성하는 알고리즘 적용 (불합리한 패배 방지).

### 특수 기능 및 아이템
1. **되돌리기 (Undo)**:
   - 직전 행동 1회 취소.
   - 보유 아이템이 있어야 사용 가능.
   - 획득처: 골드 구매 또는 일일 퀘스트/업적 보상.
2. **와일드 카드 (Wild Card / Joker)**:
   - 어떤 카드 위에도 덮을 수 있는 만능 카드.
   - 보유 아이템이 있어야 사용 가능.
   - 획득처: 골드 구매 또는 특정 콤보 미션 달성.

### 콤보 · 힌트 규칙
- **콤보**: 덱을 뽑지 않고 보드 카드를 연속으로 맞출 때만 +1. 보드의 +1 카드(덱에 카드를 더해 주는 보상 카드)는 콤보 · 콤보 게이지를 올리지도 끊지도 않는다. (클리어 보장 덱 생성기도 같은 규칙으로 계산)
- **콤보 목표 보상**: 콤보가 0이 될 때마다(판 시작 · 덱 뽑기) 목표가 [5 · 7 · 10 · 15] 중 하나로 정해지고, 콤보가 목표와 같아지는 순간 즉시 보상 (콤보가 끊길 때까지 1번).
  - 목표 5 · 7 → 덱 +1~3장 (100%) / 목표 10 · 15 → 덱 +5장 (95%) 또는 와일드 · 되돌리기 1개 (5%).
  - 보상 아이콘이 게이지 끝에서 날아가 꽂힘: 와일드 → 와일드 버튼, 되돌리기 → 되돌리기 버튼, +카드 → 덱.
  - 시스템이 준 카드(+1 보드 카드 · 보상으로 늘어난 덱 카드)는 콤보를 올리지 않는다. 목표 · 보상 순서는 판 시드로 고정 → 생성기가 클리어를 보장.
- **난이도 상향**: 정답 수순의 콤보 런 길이 +1 (쉬움 4~8 · 보통 4~6 · 어려움 3~6), 남는 여유 카드의 약 40%를 덱에서 빼서 시작 덱 감소 (평균 쉬움 11.8→11.2 · 보통 9.7→8.2 · 어려움 7.8→5.7 · 전문가 5.6→3.8장).
- **동적 레이아웃 엔진 (`js/layout-engine.js`)**: 기본 프리셋 20종(세 봉우리 · 미키 마우스 · 액자 · 카펫 · 부채 · 바람개비 · 기둥 · 블록 · 커튼 · 하트 · 온천 섬 · 다이아몬드 · 화살표 · 십자가 · 쌍둥이 탑 · 나비 · 왕관 · 골짜기 · 태양 · 고양이) + 절차적 변형 `generateLevelLayout(levelId, template, {difficulty})`.
  - 데이터: 카드 = `{x, y, z, t, rot}` — 보드 내부 카드 단위 좌표(픽셀 · vw 아님), z 큰 쪽이 덮음, t = 초반 레벨에서 먼저 잘라내는 카드(꼭대기 · 바깥 · 부채 끝), rot = 부채 기본 기울기.
  - 변형: ① 좌우 50% · 상하 35% 반전 ② 잘라내기(쉬움 ≈ 20장 → 전문가 ≈ 템플릿 전부, 최소 18장 · 최대 8장 제거, 난이도 등급으로 결정) ③ 표시 좌표 ±1.5%(카드 기준) 흩어짐 ④ 카드별 ±5° 기울기. ③④는 표시 전용이라 덮임 판정(퍼즐 논리)은 흔들리지 않는다.
  - 레이아웃 id `'<템플릿>@<시드>@<난이도>'` — 딜 시드로 템플릿을 고르고 변형하므로 재도전 · 이어하기도 같은 배치. 6,000 스테이지(300화 × 20) 모두 보이는 배치가 다르고 논리 배치(반전 · 잘라내기)는 약 1,150종.
  - 그리는 순서: 앞면 카드는 모든 뒷면 카드 위층(`--z` 1000+, 보조 안전장치).
  - **불변식: 화면에서 겹치면 반드시 퍼즐상 덮는 관계.** 렌더러는 간격을 압축하지 않고(카드 × 1.04), 템플릿은 겹치는 두 카드의 층(z)이 항상 다르도록 짜며(`TP.layoutConflicts` = 0), 폭 ≤ 8.2칸 · 높이 ≤ 1.85칸으로 휴대폰(732×412 스테이지)에 75px 카드가 그대로 들어간다. 그래서 열린(앞면) 카드가 다른 카드 뒤에 깔려 보이는 일이 구조적으로 없다 — 잘라내기 변형 뒤에도 유지 (테스트가 800판을 매 수마다 검사). 넘치면 카드를 64px까지만 줄이고 경고를 남긴다. 기울기(부채 최대 ±24°, 무작위 ±5°)와 흩어짐으로 논리상 떨어진 카드의 모서리가 닿을 수 있으므로, 변형 마지막에 **기하 정착**(`settleGeometry`: 회전 포함 실제 사각형을 분리축으로 검사해, 닿는 쌍의 기울기 · 흩어짐을 줄임)을 거친다 — `TP.layoutGeometryConflicts` = 0. 잘라내기 최소 18장.
  - 카드 플레이 화면: 탐정 책상 톤 배경(종이 + 나무 비네트), 낼 수 있는 카드 노란 네온 글로우, 상 · 하단 HUD 확대 (`css/cardscene.css`, 디자인 토큰 `--desk-* --hud-* --glow`).
  - 게임 화면 배치: 상단 왼쪽 상점 · [난이도 · 남은 카드] (배수는 ×2·×4일 때만), 상단 가운데 콤보 게이지, 상단 오른쪽 골드 · 설정 / 하단 왼쪽 고양이 · 가운데 덱 + 액티브 카드 · 오른쪽 되돌리기 · 와일드. 레벨 · 특별 할인 · 에피소드 · 수첩 · 단서 진행(12/20)은 게임 중 숨김(홈에서 확인).
- **클리어 보장 덱 진입점 `generateSolvableDeck(difficulty, boardLayout)`** (`js/core/tripeaks_core_engine.js`): ① 빈 슬롯(coveredBy) 준비 → ② 정답 제거 순서(위상 정렬) → ③ 콤보 런 분할 (`DIFFICULTY_RULES`: 쉬움 4~8 · 보통 4~6 · 어려움/전문가 3~6, 마지막 런도 최소 길이 이상) → ④ 런마다 브릿지 카드에서 ±1(K↔A) 워크로 숫자 역산 배정 → ⑤ 잉여 카드 중 난이도별 비율을 덱 맨 뒤로 (쉬움 25% · 보통 40% · 어려움 55% · 전문가 85%).
  - +1 보너스 카드와 콤보 상자 보상 카드는 콤보를 올리지도 끊지도 않으므로 런 길이에 세지 않는다 (보너스 카드는 런 안에 끼어도 길이 0).
  - 테스트: 시드 200 × 4난이도 × (특수 카드 유/무) — 정답 수순 100% 클리어, 계획 런 100% 범위 안 (실제 콤보는 숫자 재고가 바닥나 브릿지가 끼는 경우만 짧아져 약 96%), 잉여 제거 비율 ±5% 이내.
- **덱 빛남 힌트**: 보드에서 낼 카드가 없을 때 덱이 깜빡이며 "덱을 뽑으세요" 안내 — **Lv.1~2에서만** 작동. Lv.3부터는 힌트 없이 스스로 판단하고 되돌리기 · 와일드를 전략적으로 쓰도록 한다.

### 연출 (손맛 · Juiciness)
- **오가닉 보드 배치**: 보드 카드는 반듯한 격자가 아니라 장마다 -4°~+4° 비틀려 놓인다. 같은 판은 항상 같은 각도(판 번호로 고정).
- **플라잉 카드**: 카드를 맞히면 그 카드가 위로 솟았다가 포물선을 그리며 하단 액티브 자리에 0°로 착지 (0.22초, 살짝 커졌다 작아짐). 착지 시 슬롯 펄스 + 불꽃.
- **콤보 별가루**: 착지 지점에서 별이 상단 콤보 게이지로 날아감 (콤보가 클수록 많이, 최대 5개).
- **엔드게임 축포**: 클리어 시 덱에 남은 카드 수만큼 골드가 허공으로 터져 오르며 덱 숫자가 0까지 줄어든 뒤 클리어 화면으로 넘어감 (많아도 2.4초 안에 종료).
- **마스코트 리액션**: 화면 좌측 하단의 탐정 조수 고양이가 평소엔 숨 쉬듯 들썩이고, 카드를 맞힐 때마다 폴짝 뛴다.
- **콤보 게이지**: 틀 그림(ui_combo.png) 끝 소켓에 다음 콤보 상자 보상 아이콘 표시 — 와일드면 와일드카드, 덱 추가면 +N 카드 그림으로 바뀜.
- **콤보 보상 비행**: 상자가 열리면 보상 아이콘이 소켓에서 튀어나와 와일드 → 우측 하단 와일드 버튼, +N 카드 → 하단 덱으로 날아가 꽂힘 (0.65초). 도착하는 순간 와일드 아이템 지급 · 덱 숫자 증가.
- 설정 창 · 팝업은 항상 파티클 · 플라잉 카드보다 위에 표시. 기기의 '동작 줄이기' 설정을 켜면 반복 애니메이션은 멈춘다.

### 정산 구현 (`js/app.js` · `js/core/home_progression_system.js`)
- **입장 팝업** (v2, Higgsfield 아트): 프레임 `frame_entry.webp`(수사 책상 배경 — 코르크 증거판 · 사건 파일 · 돋보기 · 지문 카드, 가운데는 어둡게 비워 글씨가 잘 보임 + 금 테두리, 위 금색 제목판에 STAGE n/20). 윗줄 [난이도 EASY/NORMAL/HARD/EXPERT] [판 #시드] '걱정 마세요! …' → ×1 / ×2 / ×4 카드(선택 = `card_mult_gold` · 해금 = `card_mult_blue` · 잠김 = 사슬 `card_mult_locked` + 'LV.N 해제', ×4 잠김은 더 어둡게; 카드 안에 입장료 · 보상 범위) → 단서 안내 · 최고 별 · 이 사건 누적 별 → 별 기준 칩 → [BACK] [PLAY] + PLAY 위 말풍선(골드 ×입장료 + 하트 1). 골드 · 하트가 모자라면 PLAY 자리에 Luckiest Guy 풍 글씨 그림 '골드 충전' / '하트 충전'(`txt_gold_charge` · `txt_heart_charge.webp`). 마지막 선택 배수는 저장(`selectedMultiplier`).
- **입장(Play)**: `startStageWithBet(x)` → 하트 1 + (구간 입장료 × 배수) 즉시 차감. 골드가 모자라면 시작 불가 팝업 (필요 / 보유 · 낮은 배수로 바꾸기 · 상점 · 닫기), 하트도 차감하지 않는다.
- **클리어**: 기본 보상 = 구간 최소 + (최대 − 최소) × 성과, 성과 = 남은 덱 비율(12장 = 최대) 65% + 최고 콤보 비율(10콤보 = 최대) 35%. 최종 골드 = 기본 보상 × 배수 (+ 연승 마일스톤 골드). EXP = (45 + 최고 콤보 × 2) × (1 + (배수 − 1) × 0.25).
- **결과창**: 골드(+N)가 0부터 롤링되며 오르고, 이어서 EXP가 롤링 (틱 · 코인 효과음). 그 아래 '기본 보상 N × M배 + 연승 보너스' 계산식.
- **실패**: 골드 보상 0, 입장료는 돌려주지 않음. 실패 결과창(STAGE FAILED)에는 [HOME] / [REPLAY]만 — 하트는 입장 때 이미 썼으므로 별도 처리 없음. 연승이 끊겼으면 500G 연승 세이브 버튼을 작게 함께 표시.

## 9. 에셋 배포 · 백업 · 플랫폼 대응 (2026-10-20)

### 에셋 다이어트 (`tools/optimize_assets.py`)
- PNG 227개 → WebP (61.6MB → 6.2MB), MP3 34개 → OGG (12.8MB → 10.7MB). JPG 2,725개는 WebP 로 바꾸면 오히려 커져 유지.
- 앱에 안 들어가는 생성 원본 1.3GB(캐릭터 · 배경 원본, WAV BGM, 시트 등)는 프로젝트 바깥 `../assets_original_backup/` 으로 이동. 변환 전 PNG · MP3 원본, 치환 전 코드 사본(`_code/`), `manifest.json` 도 같은 곳.
- 결과: APK 192.6MB → 135.7MB, Git 저장소 약 120MB.

### 원본 백업 — 구글 드라이브 (수동)
- `assets_original_backup` 폴더는 Git 에 올리지 않는다. **개발자가 직접 압축해 `orokorea1@gmail.com` 구글 드라이브에 올려 보관한다.**
- 권장: `assets_original_backup_YYYYMMDD.zip` 이름으로, 원본이 바뀔 때마다(새 캐릭터 · 배경 생성, BGM 추가) 새로 올리고 이전 것은 1개 이상 남긴다.
- 원본이 필요한 도구(`tools/build_episode_backgrounds.py` · `build_character_portraits.py` · `build_bgm.py` 등)를 다시 돌릴 때는 드라이브에서 받아 `../assets_original_backup/game_assets/…` 를 프로젝트 `game_assets/` 로 되돌려 놓고 실행 → 끝나면 `optimize_assets.py --apply` 로 다시 다이어트.

### CDN 에셋 다운로드 (GCP Cloud Storage, `js/asset-manager.js`)
- 대상: 에피소드 그림(배경 · 초상화 · 썸네일 · 단서, 약 98MB) + 사운드(`sounds/sfx` · `sounds/bgm_mp3`). `tools/build_cdn_pack.py` 가 버전 이름이 붙은 zip 묶음(최대 40MB, 무압축) + `version.json` 을 `dist/cdn/` 에 만든다 → 공개 버킷에 올림.
- 묶음은 기기별: `all` = 그림 3묶음(98MB) · `android` = 사운드 OGG(10.7MB) · `ios` = 백업의 사운드 MP3(12.8MB). 기기는 `all` + 자기 플랫폼 묶음만 받는다 (안드로이드 108.7MB · iOS 110.8MB).
- 빌드: `tools/build_www.py --cdn <version.json 주소>`(또는 `TP_CDN_URL`) → CDN 폴더들을 앱에서 빼고 `js/cdn-config.js` 를 켬. 사운드는 앱에 두고 그림만 CDN 으로 하려면 `--cdn-no-audio`(묶음도 `--no-audio`). 기본 빌드는 지금처럼 모두 앱에 포함(꺼짐).
- 첫 실행(네이티브): 진행 막대 로딩 화면 '사건 파일을 준비하고 있어요' → zip 을 받으면서 바로 풀어(fflate) 기기 저장소(Directory.DATA `cdn_assets/<버전>/`)에 기록 → 새로 고침. 이후 실행은 그림 경로(`TP.EPISODES`)와 사운드 경로(`TP.AUDIO_FILES`)를 기기 저장소 주소로 바꿔 끼워 오프라인에서도 동작. 새 버전이 올라오면 다시 받고 예전 버전 폴더는 지움. 처음 실행에 오프라인이면 [다시 시도].
- 비용: 설치 1회당 약 109MB 전송. 버킷은 미국 서해안 리전(us-west1, 한국 · 일본 · 미국 출시 기준) — 항상 무료 등급(저장 5GB · 북미→인터넷 전송 월 100GB ≈ 설치 900회분)이 미국 리전에만 적용. 무료 체험 크레딧이 남은 동안은 모든 요금이 크레딧에서 차감, 체험 종료 시 결제 계정을 유료로 업그레이드해야 버킷이 유지되고 그 뒤에도 무료 등급은 계속 적용. 초과분은 GB당 $0.1대(월 설치 1만 건 ≈ 1.1TB ≈ 대략 $100대). 월 예산 알림 필수(알림만, 자동 중지 아님). Plan B: Cloudflare R2(전송 무료) · Google Play Asset Delivery — 빌드의 version.json 주소만 바꾸면 됨.

### iOS 오디오 (`js/audio-helper.js`)
- iOS(Safari · WKWebView)는 OGG Vorbis 재생이 불완전 → `Capacitor.getPlatform() === 'ios'` 이거나 브라우저가 OGG 를 못 튼다고 답하면 `TP.AUDIO_FILES` 의 경로를 `.mp3` 로 바꿔 쓴다. 안드로이드는 `.ogg`.
- CDN 빌드: iOS 기기는 CDN 의 `ios` 사운드 묶음(백업의 MP3)을 받고, 헬퍼가 확장자를 `.mp3` 로 바꾼 뒤 `TP.AssetManager.url()` 로 기기 저장소 주소를 가리킨다 — 앱 안에는 사운드가 없다.
- CDN 없는 iOS 빌드: `tools/build_www.py --platform ios`(또는 `TP_PLATFORM=ios`) — 백업의 MP3 를 앱 안 같은 경로에 넣고 OGG 는 뺀다.
- 그래서 iOS 용 MP3 원본이 담긴 `assets_original_backup/game_assets/sounds/` 는 구글 드라이브 백업에서 빠지면 안 된다.

## 10. 유저 식별 — Firebase 로그인 (2026-10-20, `js/account.js`)
- 첫 실행 때 로그인 화면 없이 **익명 계정 자동 생성** → 모든 유저가 고유 유저 ID(Firebase UID)를 가진다. 설정 → 프로필 및 계정에 '게스트 / Google 이메일'과 유저 ID(앞 8자리) 표시.

- [계정 삭제]: Firebase 사용자 영구 삭제(오래된 로그인이면 Google 재인증 후) → 새 게스트 ID → '이 기기의 진행 상황도 초기화할까요?' (Google Play 계정 삭제 정책 대응. 앱 밖 삭제 요청 웹 페이지는 출시 전 별도 준비)
- 진행 상황(세이브)은 기기에만 저장 — 계정이 바뀌어도 세이브는 그대로. 클라우드 세이브는 다음 단계.
- 고객 문의 메일에 유저 ID 자동 기입. 법적 고지의 개인정보 문구를 Firebase 처리 내용으로 갱신.
- 빌드: `mobile/android/app/google-services.json` 이 있을 때만 로그인 플러그인(@capacitor-firebase/authentication)과 Google 로그인이 들어간다. 없으면 기기 안에서 만든 ID(`local-…`)로 식별(웹 개발 서버도 같음).
- Firebase 프로젝트는 버킷과 같은 GCP 프로젝트(`project-c648076b-81ce-422b-9d4`)에 연결. 설정 순서는 `docs/FIREBASE_AUTH_GUIDE.md`.

## 11. 세이브 구조 — 기기 파일 + Google Play 게임즈 클라우드 세이브 (2026-10-20)
- 서버 비용 0: 세이브는 기기와 유저 본인의 Google 계정(Play 게임즈 저장된 게임)에만 있다.
- 정본은 기기 파일 `save_data.json`(@capacitor/filesystem, Directory.Data, 변경을 0.4초 모아서 기록 · 백그라운드 전환 시 즉시). localStorage 는 부팅용 사본이자 파일 쓰기 실패 시 폴백. 켤 때 savedAt 이 더 최근인 쪽을 쓴다.

## 12. 다국어 (한국어 · English · 日本語) — 1단계 UI (2026-10-20)
- **방식**: 한국어 원문이 곧 키(gettext 방식). 코드에서 `T('남은 카드 {n}장', { n })` → `js/lang/en.js` · `js/lang/ja.js` 의 `TP.LANG_DATA[언어]['한국어 원문']`. 번역이 없으면 한국어 그대로(깨지지 않음). `{이름}` 자리표시자는 번역문에도 똑같이.
- **데이터 이름**(상품 · 칭호 · 코스튬 · 판 모양 · 기본 닉네임 '탐정님')은 `N_('…')` 로 표시만 해 두고 화면에 그릴 때 번역. 저장값은 한국어 원문 그대로라 언어를 바꿔도 세이브가 호환됨.
- **고정 문구**(tripeaks.html 버튼 · 제목 · title/aria-label/alt/placeholder)는 `TP.i18n.applyStatic()` 이 시작 때 한 번 교체. 앞머리 이모지가 아이콘 그림으로 바뀐 글자도 찾음.
